Shared Image Transitions
Across Pages

by Fabian Müller — June 2026

The most visually striking feature of CSS View Transitions is the ability to share an element across two separate HTML pages and have the browser automatically animate between its old position and size to its new one. No JavaScript. No canvas tricks. Just CSS.

How It Works

You assign the same view-transition-name to the card image and the article hero image. Since both pages use the same shared CSS file, this is trivial — one CSS rule covers both elements.

/* Both pages use this same CSS */
.card-image, .hero-image {
  view-transition-name: article-image;
}

When the user navigates from the blog listing to the article, the browser takes a snapshot of the card image's position and size. On the new page, it finds the element with the same transition name and animates from the old snapshot to the new one.

Important Constraints

A view-transition-name must be unique on any given page. If you have a grid of 12 blog cards, each card image needs its own distinct name — typically set via inline style or a JavaScript data attribute. This demo works because there is only one card with the transition set up.

Wrapping in prefers-reduced-motion

Always wrap your entire view transition block in a @media (prefers-reduced-motion: no-preference) query. This ensures users who have opted out of animations on their OS get a plain, instant navigation instead.

@media (prefers-reduced-motion: no-preference) {
  @view-transition {
    navigation: auto;
  }
  /* All your keyframes and pseudo-elements go here */
}

View Transitions are a progressive enhancement — in browsers that don't support them (Firefox as of mid-2026), navigation just works normally. No broken experience.
