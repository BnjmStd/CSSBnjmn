Reference

Documentation

Everything you need to implement smooth cross-document view transitions in your multi-page website.

1 · Setup

Add the following to your shared CSS file. Both pages involved in a transition must include the same CSS:

@view-transition {
  navigation: auto;
}

This alone gives you a default crossfade between every page on the same origin. The transition only works within the same domain — cross-origin navigations are intentionally excluded for security.

2 · Pseudo-elements

Three pseudo-elements let you control the animation:

  • ::view-transition-group(name) — wrapper for both old and new snapshots. Set duration and easing here.
  • ::view-transition-old(name) — the snapshot of the leaving page or element.
  • ::view-transition-new(name) — the snapshot of the entering page or element.

3 · Named Groups

Use root to animate the whole page, or define a custom name to isolate a section. For example, to keep the nav bar fixed and only slide the main content:

main {
  view-transition-name: page-content;
}

::view-transition-old(page-content) {
  animation-name: slide-out;
}
::view-transition-new(page-content) {
  animation-name: slide-in;
}

4 · Shared Elements

Assign the same view-transition-name to an element on both the old and the new page. The browser captures both states and interpolates position, size, and other properties automatically.

Rule: a name must be unique per page at the moment of transition. With multiple cards, set the name dynamically via inline style or JavaScript.

5 · Accessibility

Always wrap your transitions in a reduced-motion media query:

@media (prefers-reduced-motion: no-preference) {
  /* All view transition CSS here */
}

6 · Browser Support

  • ✅ Chrome 126+
  • ✅ Edge 126+
  • ✅ Safari 18+
  • ❌ Firefox (not yet supported)

Treat this as a progressive enhancement. Unsupported browsers navigate normally.
