el problema
Detached Listeners

Cuando eliminás un elemento del DOM pero su listener no se desvincula, la referencia permanece viva en memoria. El Garbage Collector no puede limpiarlo — y el consumo crece indefinidamente.

01
AbortController
Limpiar múltiples listeners de un golpe

Pasás una signal a cada addEventListener. Cuando llamás a controller.abort(), todos los listeners vinculados a esa señal se eliminan simultáneamente — sin necesidad de guardar referencias.

const controller = new AbortController(); const { signal } = controller; btn.addEventListener('click', handler, { signal }); input.addEventListener('keydown', handler, { signal }); window.addEventListener('resize', handler, { signal }); // Un solo llamado limpia TODOS controller.abort();

02
Delegación de eventos
Un listener para todos los hijos

En vez de añadir un listener a cada ítem de una lista, colocás uno solo en el padre. Con event.target y closest() identificás qué elemento fue clickeado. Funciona incluso con nodos añadidos dinámicamente.

// ❌ Mal: N listeners items.forEach(item => item.addEventListener('click', fn) ); // ✅ Bien: 1 listener en el padre list.addEventListener('click', (e) => { const item = e.target .closest('[data-item]'); if (item) handler(item); });

03
{ passive: true }
Scroll suave sin bloquear el hilo principal

Al declarar passive: true, le prometés al navegador que nunca llamarás preventDefault(). El browser puede entonces mover el scroll en su hilo de composición sin esperar tu código JavaScript.

// ❌ Sin passive: bloquea el hilo window.addEventListener( 'touchstart', handler ); // ✅ passive: true → scroll fluido window.addEventListener( 'touchstart', handler, { passive: true } ); // 30fps → 60fps en móviles 🚀

04
{ once: true }
Auto-eliminación después de un disparo

El listener se ejecuta exactamente una vez y luego se elimina solo del DOM, como si hubieras llamado removeEventListener manualmente. Ideal para modales de bienvenida, confirmaciones o tutoriales.

// ❌ Necesita limpieza manual function handler() { doSomething(); btn.removeEventListener( 'click', handler ); } // ✅ Se limpia solo btn.addEventListener( 'click', handler, { once: true } );

Capture & Bubble
El viaje de un evento por el DOM

Cada evento recorre el DOM en dos fases: primero desciende (capture) y luego sube (bubble). Entender esto permite interceptar eventos en el momento exacto — clave para cerrar menús al clickear fuera.

// Bubble (default) — sube desde el target elem.addEventListener('click', fn); // useCapture — captura bajando elem.addEventListener( 'click', fn, { capture: true } ); // Caso de uso: cerrar menú document.addEventListener( 'click', closeMenu, { capture: true } );

Hábito de auditoría
Medir antes de optimizar

Usá la pestaña Memory en DevTools. Tomá snapshots antes y después de desmontar un componente. Si el contador de detached listeners no vuelve a cero, tenés una fuga que limpiar.
