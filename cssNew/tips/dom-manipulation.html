Patrones Modernos de Manipulación del DOM

1. querySelector.live vs .static

live HTMLCollection vs static NodeList

¿Qué está pasando aquí?

Este ejemplo demuestra la diferencia entre buscar elementos usando métodos antiguos frente a los modernos:

  • getElementsByClassName (Colección Viva): Devuelve un HTMLCollection. Está "vivo", es decir, si en el futuro se añaden o eliminan elementos del DOM que coincidan con la clase, la variable se actualiza automáticamente por detrás.
  • querySelectorAll (Colección Estática): Devuelve un NodeList. Es una "foto" (snapshot) del momento exacto en que se ejecutó la línea. Si el DOM cambia después, esta variable no se entera y sigue teniendo los mismos elementos que encontró inicialmente.

💡 Por qué es mejor usar querySelectorAll: Hoy en día se prefiere casi siempre porque es más predecible. Evita bugs extraños en bucles donde el tamaño del array cambia inesperadamente. Además, el NodeList devuelto tiene el método .forEach() incorporado nativamente, lo que facilita mucho la iteración (a diferencia del HTMLCollection, que te obliga a convertirlo en un Array normal primero).

2. classList.live

idempotent add · force-state toggle

¿Qué está pasando aquí?

La propiedad classList es la forma moderna y segura de manipular las clases CSS de un elemento desde JavaScript. Atrás quedaron los días de tener que modificar el string completo de className o usar expresiones regulares.

  • Idempotencia con .add(): Puedes llamar a classList.add('clase') todas las veces que quieras. Si la clase ya existe, el navegador simplemente lo ignora. No duplicará la clase en el HTML (nunca verás algo como class="box active active"). Esto significa que no necesitas escribir código extra como if (!box.classList.contains(...)) antes de añadirla.
  • Toggle con Estado Forzado: El método .toggle('clase') normalmente añade la clase si no está, y la quita si está. ¡Pero tiene un superpoder oculto! Puedes pasarle un segundo parámetro opcional (un booleano). Si le pasas true, forzará a que la clase se añada. Si le pasas false, forzará a que se quite. Esto es increíblemente útil para sincronizar clases CSS con el estado de tu aplicación (por ejemplo, sincronizar la clase 'active' con la variable isLoggedIn).

3. replaceChildren.live vs innerHTML

innerHTML parses HTML · replaceChildren inserts text

¿Qué está pasando aquí? (Prevención de XSS)

Este ejemplo muestra una diferencia crítica de seguridad entre insertar contenido con innerHTML y hacerlo con métodos modernos como replaceChildren().

  • El peligro de innerHTML: Cuando asignas un string a innerHTML, el navegador evalúa y ejecuta cualquier etiqueta HTML que encuentre. Si ese string viene de un usuario malintencionado (un "payload" como <img src=x onerror="hacked()">), el navegador intentará cargar la imagen, fallará, y ejecutará el script malicioso que está en onerror. Esto abre la puerta a ataques Cross-Site Scripting (XSS).
  • La seguridad de replaceChildren: Si le pasas un string directamente a replaceChildren(string), el navegador lo trata estrictamente como texto plano. No importa si contiene etiquetas HTML; simplemente las imprimirá en pantalla de forma visual y segura, sin ejecutarlas jamás.

💡 Regla de oro: Si el contenido proviene de un usuario (inputs, comentarios, base de datos), NUNCA uses innerHTML directamente con ese texto. Usa textContent para modificar el texto interno, o replaceChildren() si quieres vaciar un elemento y añadirle nuevo texto plano de forma segura.

4. delegation + AbortController

one parent listener · one abort() removes it

¿Qué está pasando aquí?

Este ejemplo combina dos patrones avanzados muy potentes:

  • Delegación de Eventos (Event Delegation): En lugar de añadir 40 "escuchadores" de eventos individuales (uno por cada cuadrito), añadimos un solo escuchador al contenedor padre (el "grid"). Usamos e.target.closest('.item') para saber qué cuadrito fue clicado. Esto ahorra muchísima memoria y mejora el rendimiento drásticamente en listas largas.
  • AbortController para limpiar eventos: Tradicionalmente, para usar removeEventListener necesitabas guardar la referencia exacta a la función que usaste en addEventListener. Con la API moderna AbortController, puedes pasar su signal como una opción al añadir el evento. Cuando quieras eliminar el evento (o múltiples eventos a la vez asociados a esa señal), simplemente llamas a ctrl.abort(). Es infinitamente más limpio.

5. DocumentFragment

batch inserts · 1 reflow

¿Qué está pasando aquí? (Rendimiento)

Cuando necesitas insertar muchos elementos nuevos en el DOM (por ejemplo, renderizar una lista de miles de items), la forma en que lo haces afecta muchísimo al rendimiento.

  • Mala práctica (Bucle directo): Si haces contenedor.appendChild(elemento) dentro de un bucle de 1000 iteraciones, estás obligando al navegador a recalcular el diseño de la página (reflow) y repintarla 1000 veces. Esto bloquea la interfaz de usuario.
  • Buena práctica (DocumentFragment): Un DocumentFragment es como un DOM en miniatura "en memoria" (invisible). Puedes añadirle 1000 elementos dentro de un bucle instantáneamente (cero reflows). Cuando terminas, haces un único contenedor.appendChild(fragmento). El navegador toma todos los hijos del fragmento y los inserta de golpe en el DOM real, provocando un solo reflow.

💡 Haz la prueba: Pulsa los botones para insertar 1000 pequeños cuadrados. En ordenadores modernos la diferencia puede ser de pocos milisegundos, pero en dispositivos móviles o con listas gigantescas, usar DocumentFragment es la clave (y es lo que usan frameworks como React o Vue internamente).
