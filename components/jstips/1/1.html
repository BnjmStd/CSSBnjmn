01 SCOPE Scope & Hoisting — var vs let 0:30 – 1:25 ▶

Hoisting es el proceso por el que el motor JS mueve las declaraciones al inicio de su scope antes de ejecutar el código. var se eleva y se inicializa como undefined. let y const también se elevan, pero quedan en la Zona Muerta Temporal (TDZ) — acceder a ellas antes de su declaración lanza un ReferenceError.

JS 
// ── var ──────────────────────────────────
console.log(nombre); // undefined  ← hoisted
var nombre = 'Benjamín';

// ── let / const ──────────────────────────
console.log(edad);   // ❌ ReferenceError (TDZ)
let edad = 25;

// ── Scope de función vs. bloque ──────────
function ejemplo() {
  if (true) {
    var   x = 1; // accesible en toda la función
    let   y = 2; // solo dentro del bloque {}
    const z = 3; // solo dentro del bloque {}
  }
  console.log(x); // 1   ✅
  console.log(y); // ❌  ReferenceError
}
varScope de función. Hoisted como undefined. Puede redeclararse.
letScope de bloque. Hoisted pero en TDZ. No puede redeclararse.
constScope de bloque. Igual que let + inmutable (la referencia, no el contenido).
Regla prácticaUsa siempre const por defecto. let si necesitas reasignar. Olvida var.
02 CLOSURE Closures 1:26 – 2:13 ▶

Una closure es una función que recuerda el entorno léxico en el que fue creada, incluso después de que la función externa haya terminado. Permite crear variables privadas y fábricas de funciones.

JS 
// ── Contador privado ─────────────────────
function crearContador() {
  let cuenta = 0; // variable privada

  return {
    incrementar: () => ++cuenta,
    obtener:     () => cuenta,
  };
}

const contador = crearContador();
contador.incrementar(); // 1
contador.incrementar(); // 2
contador.obtener();     // 2

// ── Fábrica de multiplicadores ───────────
const multiplicarPor = (factor) =>
  (n) => n * factor;

const doble  = multiplicarPor(2);
const triple = multiplicarPor(3);
doble(5);  // 10
triple(5); // 15
MEMOIZACIÓN 
// ── Memoización: caché de resultados ─────
function memoize(fn) {
  const cache = {}; // la closure recuerda este objeto

  return function(...args) {
    const key = JSON.stringify(args);
    if (key in cache) {
      console.log('desde caché');
      return cache[key];
    }
    cache[key] = fn(...args);
    return cache[key];
  };
}

const factorial = memoize((n) =>
  n <= 1 ? 1 : n * factorial(n - 1)
);

factorial(5); // calcula → 120
factorial(5); // desde caché → 120 ⚡
CLOSURE EN LOOPS 
// ── El clásico bug de var en bucles ──────
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 3, 3, 3  ⚠️  (var comparte scope)

// ── Solución con let (scope de bloque) ───
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// Output: 0, 1, 2  ✅  (cada iter. tiene su propio i)

// ── Solución clásica con IIFE (pre-ES6) ──
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 100);
  })(i); // captura i como j en cada iteración
}
// Output: 0, 1, 2  ✅
MÓDULO IIFE 
// ── Patrón módulo con IIFE ───────────────
// Immediately Invoked Function Expression
const CarritoModule = (() => {
  let items = []; // privado, inaccesible desde fuera

  return {
    agregar(item)  { items.push(item); },
    eliminar(item) {
      items = items.filter(i => i !== item);
    },
    total()        { return items.length; },
    listar()       { return [...items]; }, // copia
  };
})(); // ← se invoca inmediatamente

CarritoModule.agregar('zapatillas');
CarritoModule.agregar('camiseta');
CarritoModule.total();   // 2
CarritoModule.listar();  // ['zapatillas', 'camiseta']
// items  → ❌ undefined (completamente privado)
¿Qué recuerda?Variables del scope externo, parámetros y el scope global al momento de creación.
MemoizaciónCache de resultados costosos. La closure guarda el objeto cache entre llamadas.
var en loopsComparte la misma variable. Usa let o una IIFE para capturar cada valor.
Módulo IIFEPatrón clásico para encapsular estado privado antes de los módulos ES6.
03 THIS El keyword this 2:14 – 2:59 ▶

this no depende de dónde se escribe la función, sino de cómo se invoca. Las arrow functions no tienen su propio this; heredan el del scope donde fueron definidas.

JS 
const obj = {
  nombre: 'Bnjmn',

  // 1) Método → this = obj
  saludar() {
    console.log(this.nombre); // 'Bnjmn' ✅
  },

  // 2) Arrow function → this heredado
  saludarArrow: () => {
    console.log(this?.nombre); // undefined ⚠️
  },
};

obj.saludar();       // 'Bnjmn'
obj.saludarArrow(); // undefined

// 3) Función suelta → undefined (strict mode)
const fn = obj.saludar;
fn(); // undefined en strict mode

// 4) bind / call / apply → this explícito
const fnBound = obj.saludar.bind({ nombre: 'JS' });
fnBound(); // 'JS'
Método de objetothis = el objeto antes del punto.
Arrow functionNo tiene this propio. Hereda del scope externo.
Función libreundefined en strict mode, globalThis en modo normal.
bind/call/applyPermiten asignar this de forma explícita.
04 IGUALDAD == vs === 3:00 – 3:55 ▶

== realiza coerción de tipos antes de comparar, convirtiendo los operandos a un tipo común de formas a veces sorprendentes. === (igualdad estricta) compara tipo y valor sin conversiones. Usa siempre ===.

== coerción
0    ==  ''        // true  ⚠️
0    ==  '0'       // true  ⚠️
0    ==  false     // true  ⚠️
''   ==  false     // true  ⚠️
null ==  undefined // true  ⚠️
[1]  ==  1         // true  ⚠️
=== estricto
0    === ''        // false ✅
0    === '0'       // false ✅
0    === false     // false ✅
''   === false     // false ✅
null === undefined // false ✅
[1]  === 1         // false ✅
Excepción válida de ==x == null atrapa tanto null como undefined sin más coerciones.
Regla de oroUsa === siempre. Sé explícito con las conversiones cuando las necesites.

06 ASYNC Promises & Async/Await 5:02 – 5:44 ▶

Una Promise representa un valor futuro (pending → fulfilled | rejected). async hace que una función siempre devuelva una Promise. await pausa la ejecución dentro de esa función hasta que la Promise se resuelve.

JS 
// ── Promise manual ───────────────────────
const esperar = (ms) =>
  new Promise((resolve) => setTimeout(resolve, ms));

// ── .then() chaining ─────────────────────
esperar(1000)
  .then(() => console.log('1s pasado'))
  .catch((e) => console.error(e));

// ── async / await (más limpio) ───────────
async function main() {
  try {
    await esperar(1000);
    console.log('1s pasado');

    // paralelo: esperar ambas a la vez
    const [a, b] = await Promise.all([
      fetch('/api/a').then(r => r.json()),
      fetch('/api/b').then(r => r.json()),
    ]);
  } catch (e) {
    console.error(e);
  }
}
main();
async devuelve PromiseAunque escribas return 42, obtienes Promise<42>.
await solo en asyncNo puedes usar await fuera de async (excepto top-level en módulos ES).
Manejo de erroresUsa try/catch con await; con .then() usa .catch() al final.
Promise.all vs .allSettledall falla rápido; allSettled espera todas aunque fallen.
07 PERF Debounce vs Throttle 5:45 – 6:25 ▶

Ambas técnicas limitan la frecuencia de ejecución de una función. Debounce espera a que el usuario deje de disparar el evento — ideal para búsquedas. Throttle garantiza que la función se ejecute máximo una vez cada N ms — ideal para scroll y resize.

⏳ Debounce
function debounce(fn, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(
      () => fn(...args), ms
    );
  };
}
// Solo ejecuta al PARAR de escribir
const buscar = debounce(
  query => fetchResults(query), 300
);
⚡ Throttle
function throttle(fn, ms) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= ms) {
      last = now;
      fn(...args);
    }
  };
}
// Máx. 1 vez cada 100ms
const onScroll = throttle(
  () => updateUI(), 100
);
Debounce — cuándoBúsqueda en tiempo real, validación de formulario, resize (solo resultado final).
Throttle — cuándoScroll infinito, mousemove, juegos, actualizaciones de UI continuas.
En producciónUsa _.debounce / _.throttle de Lodash para manejar edge cases correctamente.
